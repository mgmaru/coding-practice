# アルゴリズム学習ロードマップ

> **前提**: バックエンド / インフラ職への転職を目的とした独学（想定 4ヶ月）
> **方針**: 実装は Go で自力実装（標準ライブラリの中身を自分で書く）

---

## Tier 分けの基準

| 軸 | 内容 |
|---|---|
| **A. 依存関係** | これを知らないと次が理解できない、という順序制約 |
| **B. 実務頻度** | バックエンド/インフラで実際に顔を出す頻度 |
| **C. 習得コスト** | 自力実装まで含めた所要時間 |

⚠️ **Tier は「重要度順」ではなく「学習順序（依存関係）」です。**

- 実務価値の順： `Tier 4 > Tier 1 > Tier 3 > Tier 0 > Tier 2`
- 学習順序の順： `Tier 0 → 1 → 2 → 3 → 4`

Tier 4 が最後なのは価値が低いからではなく、**前提知識が必要だから**。

## Tier 0 — 計算量の言語（1週間）

**基準: 軸A のみ。すべての判断の共通言語。**

- 漸近記法（O / Ω / Θ）
- **N と実行時間の対応表**（例: N=10⁵ なら O(N log N) まで）
- 償却計算量（動的配列の push が平均 O(1) になる理由）
- 時間 ↔ 空間のトレードオフ

---

## Tier 1 — データ構造（5週間）★本丸

**基準: 軸B（頻度）が最優先。かつ Tier 2/3 の部品でもある。**

| データ構造 | 押さえる点 | 実務での顔 |
|---|---|---|
| 配列 / 動的配列 | メモリ連続性、キャッシュ効率、拡張の償却 | Go `slice` / Rust `Vec` |
| 連結リスト | **実務でほぼ使わない理由**を説明できること | LRU キャッシュの内部 |
| **ハッシュテーブル** ★ | ハッシュ関数、衝突解決（チェイン法 / オープンアドレス法）、リサイズ、最悪 O(N) | `map` / `HashMap` — **最頻出** |
| スタック / キュー | — | 呼び出しスタック、ジョブキュー |
| **ヒープ（優先度付きキュー）** ★ | 二分ヒープの構造、push/pop が O(log N) | スケジューラ、Top-K、レート制限 |
| 二分探索木 / 平衡木 | BST が偏る問題、赤黒木・AVL の動機 | `TreeMap`、DB インデックス |
| **B木 / B+木** ★ | なぜディスクでは二分木でなく B 木か（ページ I/O） | **RDB インデックスの正体** |
| Union-Find | 経路圧縮、union by rank | クラスタリング、連結性判定 |
| Trie | — | ルーティング、オートコンプリート、IP プレフィックス |

## Tier 2 — 基本アルゴリズム（4週間）

**基準: 軸A が主。自分で書く機会は少ないが、Tier 3/4 の語彙になる。**

- **ソート**
  - マージソート（安定・分割統治の原型）
  - クイックソート（最悪 O(N²) になる理由）
  - ヒープソート
  - **外部ソート**（メモリに載らないデータ → 実務直結）
- **二分探索**
  - ソート済み配列上
  - **「答えで二分探索」**（めぐる式。汎用テク）
- **再帰と分割統治** — 停止条件、スタック深さ、末尾再帰
- **全探索** — bit 全探索、順列全探索（そもそも全部試せるかを計算量で判断）
- **貪欲法** — **貪欲が正しくなる条件**を説明できること
- **累積和 / 尺取り法** — 区間クエリの前処理。ログ集計で即使える
- **動的計画法（DP）** ※例外項目
  - ナップサック、LCS、区間 DP
  - メモ化再帰 ↔ 漸化式の往復
  - **実務頻度は低い**。コーディングテスト対策 + 「部分問題への分解」思考のため
  - **時間が足りなくなったら真っ先に削ってよい**

---

## Tier 3 — グラフ（2週間）

**基準: 軸B。依存関係・ネットワーク・データフローは全部グラフ。**

| 項目 | 実務での顔 |
|---|---|
| グラフの表現（隣接リスト vs 隣接行列） | メモリ量を計算できること |
| **DFS / BFS** | 探索全般（BFS は最短路になる） |
| **トポロジカルソート** | ビルド依存、DAG スケジューリング、マイグレーション順序 |
| 閉路検出 | デッドロック検出 |
| **ダイクストラ法** | 最短経路（ヒープと組み合わせる） |
| 最小全域木（Kruskal） | Union-Find の応用 |

> ベルマンフォード / ワーシャルフロイド / 最大流 は **後回しで OK**

---

## Tier 4 — バックエンド・インフラ固有（4週間）★差別化ポイント

**基準: 軸B が最大。ただし Tier 1 がないと理解できないので最後。**
**→ 職務経歴書で最も効くのはここ。**

| 項目 | 内容 |
|---|---|
| **LSM-Tree** | vs B+木。書き込み最適化（RocksDB / Cassandra） |
| **Bloom Filter** | 確率的データ構造。「無い」ことを高速判定 |
| **HyperLogLog** | 近似カウント（ユニークユーザー数） |
| **Consistent Hashing** | シャーディング、ノード追加時の再配置最小化 |
| **LRU / LFU キャッシュ** | 実装できること（面接頻出） |
| **レート制限** | Token Bucket / Leaky Bucket / Sliding Window |
| **Raft** | 分散合意。読むだけで OK、実装は不要 |
| **CRDT / ベクタークロック** | 結果整合性 |
| **Merkle Tree** | 差分検出（Git / 分散 DB） |

## AI の使い方（4つのルール）

1. **AI に実装させない。** 必ず自分でゼロから書く
2. 書いた **後** にレビューさせる（「計算量は？」「このコーナーケースは？」）
3. **反例を作らせる**（「私の貪欲法が誤りになる入力を出して」）
   → 独学の最大の弱点＝**誤った理解の固定化**を潰せる
4. **「なぜこのデータ構造でないとダメか」を説明させる**
   → `map` で足りるのにセグ木を使う、といった判断ミスを防ぐ

既存の学習ノート運用（困りポイント → 自分の仮説 → AI で埋める → 未解決リスト）をそのまま適用する。
