# 01_basics — データ操作ドリル

組み込みコレクションの流暢さを鍛える15問。実コードに繰り返し出てくる操作パターンに絞ってある。

## このドリルの目的

- **「設計はできるが実装で詰まる」を埋める。** 組み込みコレクション（list / map / set など）を、設計判断としてではなく「手の速さ・反射」のレベルで扱えるようにする。
- **偏りを潰す。** ツール開発（logstat 等）だけだと出番が偏る操作を、網羅的かつ短時間で反復する。無意識に避けがちな苦手を、意識的に踏みにいく。
- **概念と言語表現を分けて習得する。** 同じ15問を4言語で回し、(1) 操作の概念（Go 1周目）と (2) 各言語らしい書き方・固有の罠（2周目以降）を切り分けて身につける。
- **ゴールは「解けること」ではなく「反射で書けること」。** 各問の `狙い` は実コードに頻出する操作パターン1つに対応している。詰まらず手が動く状態を目指す。

**回し方**: Go → Python → Rust → TypeScript の順に1周ずつ。実装は自分、レビューはAI。
入力例・出力例はそのままテストケースとして使える粒度にしてある（境界条件は補足に明記）。

## Tier 1 — コレクション基礎

### 1. フィルタ＆変換
偶数だけ取り出して2乗する。元の配列は変更せず、新しい配列を返す。

- 狙い: 非破壊変換の癖をつける（元を壊さず新しい列を返す）。map / filter の基本形。
- 入力: `[1, 2, 3, 4, 5, 6]`
- 出力: `[4, 16, 36]`

### 2. 畳み込み（一度のループで）
合計・最大・最小を **一度のループで同時に** 求める。

- 狙い: 複数の集計を1パスにまとめる。reduce / fold の感覚を持つ。
- 入力: `[3, 1, 4, 1, 5, 9, 2, 6]`
- 出力: `合計=31, 最大=9, 最小=1`
- 補足: 空配列のときの戻り値を自分で決めて受け入れ条件に書く。

### 3. 存在判定の高速化
A の各要素が B に含まれるか判定し、含まれるものだけ返す。

- 狙い: 線形探索とset化のコスト差を体で覚える（O(n²) → O(n)）。
- 入力: `A = [1, 2, 3, 4, 5]`, `B = [2, 4, 6]`
- 出力: `[2, 4]`
- 補足: 線形探索版とset化版の両方を書き、計算量の差を notes に1行残す。

## Tier 2 — 集約と索引

### 4. 頻度カウント
要素ごとの出現回数を数える。

- 狙い: 最頻出の集約パターン。map をカウンタとして使う手筋。
- 入力: `["apple", "banana", "apple", "cherry", "banana", "apple"]`
- 出力: `{"apple": 3, "banana": 2, "cherry": 1}`

### 5. グループ化（group-by）
指定キーごとに値をまとめる。

- 狙い: キーごとにリストを溜める。あらゆる集計の土台。
- 入力: `[{name:"Sato", dept:"Sales"}, {name:"Suzuki", dept:"Dev"}, {name:"Tanaka", dept:"Sales"}]`
- 出力: `{"Sales": ["Sato", "Tanaka"], "Dev": ["Suzuki"]}`
- 補足: 各グループ内は入力の出現順を保つこと。

### 6. 重複排除・順序保持
重複を消すが、最初の出現順は保つ。

- 狙い: set の副作用（順序喪失）を理解し、順序を保つ手筋を持つ。
- 入力: `[3, 1, 3, 2, 1, 4]`
- 出力: `[3, 1, 2, 4]`
- 補足: 素朴にsetへ入れると順序が壊れる。そこが論点。

### 7. ルックアップ表
リストをキーで引ける表に変換し、別のキー列から引く。

- 狙い: 繰り返し引くなら先に索引化する、という判断を身につける。
- 入力: `users = [{id:1, name:"A"}, {id:2, name:"B"}]`, `引くid = [2, 1, 2]`
- 出力: `["B", "A", "B"]`
- 補足: 毎回リストを線形探索せず、先にmapへ変換してから引く。

### 8. 複数キーソート（安定）
姓の昇順 → 年齢の降順 で並べる。

- 狙い: カスタム比較と安定性を扱う。複合キーの並べ替え。
- 入力: `[{last:"Sato", age:30}, {last:"Ito", age:25}, {last:"Sato", age:40}]`
- 出力: `[{Ito, 25}, {Sato, 40}, {Sato, 30}]`
- 補足: 同姓内で元の相対順が崩れないこと（安定ソート）。

## Tier 3 — ネストと結合

### 9. 二段集約（map of map）
日付ごと × レベルごとの件数を数える。logstat本体と地続き。

- 狙い: ネストしたmapを構築する。logstat の中核そのもの。
- 入力: `[{date:"06-01", level:"INFO"}, {date:"06-01", level:"ERROR"}, {date:"06-01", level:"INFO"}, {date:"06-02", level:"INFO"}]`
- 出力: `{"06-01": {"INFO": 2, "ERROR": 1}, "06-02": {"INFO": 1}}`

### 10. 平坦化
リストのリストを1段に潰す。

- 狙い: ネスト構造を1段に落とす基本操作。
- 入力: `[[1, 2], [3], [4, 5, 6]]`
- 出力: `[1, 2, 3, 4, 5, 6]`

### 11. 結合（inner join）
2つのリストを共通キーで突き合わせ、両方に存在するものだけまとめる。

- 狙い: 2つのデータセットをキーで突き合わせる。DB的な join の感覚。
- 入力:
  `users = [{id:1, name:"A"}, {id:2, name:"B"}]`
  `orders = [{userId:1, item:"x"}, {userId:1, item:"y"}, {userId:3, item:"z"}]`
- 出力: `[{name:"A", item:"x"}, {name:"A", item:"y"}]`
- 補足: id=2（注文なし）と userId=3（ユーザーなし）は落ちる。

### 12. 反転（invert）
キーと値を入れ替える。値が重複するのでキーごとにリスト化する。

- 狙い: 多対一を一対多へ組み替える。map変形の応用。
- 入力: `{"a": 1, "b": 2, "c": 1}`
- 出力: `{1: ["a", "c"], 2: ["b"]}`

## Tier 4 — 順序・ウィンドウ

### 13. 累積和
先頭からの累積を返す。

- 狙い: 前の状態を持ち越しながら走査する。
- 入力: `[1, 2, 3, 4]`
- 出力: `[1, 3, 6, 10]`

### 14. スライディングウィンドウ（移動平均）
直近 N 件の移動平均を返す。

- 狙い: 固定幅の窓を滑らせる。境界（窓が満たない先頭）の扱い。
- 入力: `[1, 2, 3, 4, 5]`, `N = 3`
- 出力: `[2.0, 3.0, 4.0]`
- 補足: 窓が満たない先頭（最初の N-1 件）は出力しない。

### 15. Top-N
頻度マップから上位 N 件を多い順で返す。

- 狙い: 部分的な順位付け。全ソート以外の選択肢を意識する。
- 入力: `{"a": 5, "b": 2, "c": 8, "d": 1}`, `N = 2`
- 出力: `[("c", 8), ("a", 5)]`
- 補足: 全ソートで解いてよい。ただし「ヒープ／部分ソートという選択肢がある」ことは notes に1行残す。

## 言語別に踏み抜く罠（2周目以降の主役）

| 言語 | 注意 |
| --- | --- |
| Go | mapのイテレーション順は非決定 / nil mapへの代入はpanic / `append`とエイリアシング / `v, ok := m[k]` |
| Python | ミュータブルなデフォルト引数 / dictは挿入順保持 / 浅いコピーと深いコピー / `defaultdict`・`Counter`・内包表記 |
| Rust | 所有権・借用 / `HashMap::entry` / `Option`の扱い / `iter().map().filter().fold().collect()` |
| TypeScript | キーが文字列以外なら`Map` / 参照等価 / **`sort()`のデフォルトは文字列比較** / イミュータブルな更新 |
